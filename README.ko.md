# 기존 Render 디스코드 봇에 유튜브 알림 붙이기

새 공개 업로드와 실제로 시작한 공개 라이브만 지정한 디스코드 채널에 알립니다. 새 봇, 새 Render 서비스, 외부 DB가 필요하지 않습니다. 기존 명령어와 `on_ready`는 교체하지 않습니다.

## 설치

1. `youtube_alerts.py`를 기존 `bot.py`와 같은 폴더에 복사합니다. 기존 Python 3.9 이상, `discord.py` 환경을 사용합니다. HTTP 클라이언트 `aiohttp`는 `discord.py`의 의존성입니다. 시작 명령이나 기존 봇 토큰을 바꾸지 않습니다.
2. 기존 `bot.run(TOKEN)` **바로 위**에 다음 두 줄을 한 번만 추가합니다. 기존 `bot.run(...)` 줄은 그대로 하나만 둡니다.

   ```python
   from youtube_alerts import install as install_youtube_alerts
   install_youtube_alerts(bot)
   ```

   `render-bot.patch`는 같은 두 줄을 넣는 선택 사항입니다. 수동 편집과 패치를 둘 다 적용하지 마세요.
3. 기존 Render 서비스의 **Environment**에서 아래 세 값을 설정합니다. 기존 값은 지우지 마세요. 키나 토큰을 소스, 패치, 채팅에 넣지 마세요.

   | 변수 | 값 |
   | --- | --- |
   | `YOUTUBE_CHANNEL_ID` | 알림 대상 유튜브 채널 ID (`UC`로 시작하는 24자, `@핸들`이나 URL 아님) |
   | `DISCORD_NOTIFY_CHANNEL_ID` | 보낼 디스코드 **텍스트 채널**의 숫자 ID. 개발자 모드에서 채널 우클릭 → 채널 ID 복사 |
   | `YOUTUBE_API_KEY` | 기존 Google Cloud 프로젝트에서 YouTube Data API v3 사용이 가능한 서버용 키. API 제한을 YouTube Data API v3로 설정 권장 |

4. 해당 디스코드 채널에서 봇에 **채널 보기**, **메시지 보내기**를 허용합니다. 특별한 인텐트나 관리자 권한은 필요 없습니다. 코드를 반영한 뒤 기존 서비스 한 인스턴스만 실행합니다. 변수가 빠지면 알림만 비활성화됩니다. `YouTube alert baseline ready`가 INFO 로그에 뜨면 그 시점 이후의 새 이벤트부터 대상입니다. 첫 동작 확인용으로 옛 영상이 발송되지 않습니다.

## 알림 기준과 한계

- 약 2분마다 공개 RSS와 업로드 재생목록(`UC…` → `UU…`, 최신 최대 50개)의 ID를 합칩니다. 둘 중 하나만 성공해도 처리합니다. 공식 `videos.list`에서 대상 채널·공개 여부·라이브 상태를 확인합니다. 공개 Shorts도 일반 업로드 대상입니다. 예약 자체나 종료 방송 다시보기는 보내지 않습니다. 실제 시작 시각과 현재 라이브 상태가 **둘 다** 확인될 때만 라이브를 알립니다. 프리미어 등 YouTube가 라이브와 동일하게 표시하는 콘텐츠는 구분되지 않을 수 있습니다.
- 처음 확인한 시각 이전의 업로드·진행 중이던 방송은 보내지 않습니다. 발견한 예약 ID를 별도로 추적해 목록에서 사라져도 계속 확인합니다. 30일 동안 API에서 추적 상태를 재확인하지 못한 ID는 정리합니다. 성공한 알림 ID는 7일간 보관하며, 그 이후에도 오래된 시각의 영상은 보내지 않습니다.
- 송신 실패 시 성공으로 기록하지 않습니다. 다음 검사에서 여전히 유효할 때 재시도합니다. 업로드 공개/방송 시작 후 1시간을 넘기거나 방송이 종료되면 보내지 않습니다. 제목에 `@everyone` 등이 있어도 멘션을 허용하지 않습니다. API/통신 오류 시 전체 검사 재시도 간격은 최대 30분으로 늘어납니다. 대개 2분당 재생목록 1회 + 영상 상세 1회이며 50개 넘는 ID는 나눠 조회합니다. RSS에는 API 키를 보내지 않습니다.
- 기본 상태 파일은 실행 폴더의 `.youtube-alerts-state.json`입니다. 봇은 같은 폴더에 임시 파일을 쓴 뒤 원자적으로 교체합니다. 키/제목은 저장하지 않습니다. 저장 실패 시 메모리로 계속 동작합니다. **기존에** 영구 디스크가 있다면 선택 변수 `YOUTUBE_STATE_FILE`을 그 디스크의 쓰기 가능한 파일 경로로 지정하세요. 새 디스크는 필수가 아닙니다. 상태 파일은 소스에 커밋하지 마세요.
- Render의 일반 로컬 파일은 재배포·재시작 시 사라질 수 있습니다. 재시작 때 현재 상태를 새 기준으로 삼아 과거 알림을 쏟아내지 않습니다. 파일이 살아 있으면 미전송 건만 유효성 확인 후 재시도하며 예약 추적도 이어집니다. 파일이 없으면 오래된 예약 추적·미전송 건과 중단 중 발생한 이벤트를 놓칠 수 있습니다. API 반영 지연, 두 목록에 나타나지 않은 방송, 두 검사 사이에 끝난 짧은 방송은 감지할 수 없습니다. Discord 수신 직후 프로세스가 종료되거나 응답이 유실되면 중복 가능성이 있어 정확히 한 번 전송을 보장하지 않습니다. 여러 인스턴스를 병렬 실행하지 마세요.

## 오프라인 테스트와 제거

압축을 푼 폴더에서 `python -m unittest -v test_youtube_alerts`를 실행합니다. 표준 라이브러리와 가짜 응답으로 검사하며 API 키나 디스코드 접속은 필요하지 않습니다. 실제 API 키·할당량·채널 권한·서비스 배포 상태는 이 검사로 확인되지 않습니다.

끄려면 세 환경변수 중 하나를 제거하고 재시작하세요. 완전히 제거하려면 위 두 줄을 지운 후 `youtube_alerts.py`를 제거합니다. 기존 `bot.run(...)`은 유지합니다.
